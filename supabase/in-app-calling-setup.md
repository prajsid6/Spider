# In-app calling setup

Spider uses browser WebRTC audio calls. Call signaling is sent over private Supabase Realtime broadcast channels, and temporary TURN credentials are issued only to the requester or accepted helper for a connected request. Phone numbers are not shown to either participant.

## Supabase setup

1. Apply `supabase/in_app_call_migration.sql` in the Supabase SQL Editor (or deploy it with your normal migration workflow). The policies restrict private call channels to the requester and the accepted helper.
2. Configure a TURN server with Coturn REST authentication (`use-auth-secret`) and a private shared secret. Keep this secret on the server; do not add it to a `VITE_` variable or the browser bundle.
3. Configure and deploy the Edge Function:

   ```powershell
   supabase secrets set TURN_URLS="turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp,turns:turn.example.com:5349?transport=tcp"
   supabase secrets set TURN_SHARED_SECRET="your-private-coturn-shared-secret"
   supabase functions deploy turn-credentials
   ```

   Use your own TURN host and shared secret. The TURN server must use the same secret to validate the short-lived HMAC-SHA1 credentials generated by the function.
4. Ensure the site is served over HTTPS. Browsers require a secure context and microphone permission for audio calls. Both participants must be signed in and have the connected request open in Spider to receive or place a call.

The function issues credentials that expire after one hour and checks the caller's Supabase identity against the accepted request/helper pair before returning them. Calls require an available TURN service for reliable connections across restrictive networks.
